# Driver threads get a crash-safe cleanup path, and Crack stops mistaking a crashed run for a completed one

**Status: implemented.** All six files in the Implementation plan below are done, plus the New/updated tests section's six new tests (`test_jobs.py`, `test_discovery_acceptance.py`, `test_capture_acceptance.py`, `test_enumerate_acceptance.py`, `test_crack_acceptance.py`, `test_crack_view.py`) — full suite passes (210, up from 204).

Every job-driver thread (`Discovery._drive`, `Capture._drive`, `Crack._drive`, `Enumerator._drive`) does its real setup — opening this thread's own SQLite connection via `self._new_connection_scope()`, plus a few trivial local variables — *before* its own `try:/finally:` block starts. If that setup raises, the thread dies with none of its cleanup ever running: the job row stays `RUNNING` in the database until the next app launch's reconciliation pass, and for Discovery/Capture/Enumerator specifically, the adapter's single-radio reservation (`rf.py`'s `RadioController._current`) never gets released — every later Discovery/Capture/Enumerate attempt raises `AdapterBusy` for the rest of that *live* session, with no recovery short of restarting AirCommand. Separately, and independently: `Crack._drive` never checks `hashcat`'s exit code at all — if `hashcat` dies immediately (bad args, no GPU driver, an unreadable `.cap` file), the existing code can't tell that apart from "ran the whole wordlist, key not found," and durably records a crashed run as `outcome=Exhausted()`, `stop_reason=StopReason.COMPLETED` — wrong data in a security-audit trail, not just a missing error message.

We decided: (1) harden `JobRegistry.mark_terminal()` so a failing/unavailable database write can never block the in-memory cleanup (job-registry bookkeeping, `wait_for_test()`'s unblocking) that the rest of the live session depends on; (2) in each of the four drivers, widen the existing `try:` to start before `self._new_connection_scope()`, so the *same, already-correct* `finally` block runs even if that call itself raises; (3) give `Crack._drive` the same `StopReason.ERROR`-on-unexpected-exit treatment `Capture._drive` already has, inferred from `hashcat`'s real exit code rather than purely from the on-disk outfile's presence.

## Why

This was found by re-reading every driver's own `_drive` against the same standard ADR-0008 already established for Discovery/Capture (a driver's cleanup must not depend on an assumption that can fail silently) — not hypothesized, each claim below was checked against the current code:

- **The pre-`try` gap is real and identical across all four drivers.** `discovery.py`, `capture.py`, `crack.py`, and `enumerate.py` each call `db_scope = self._new_connection_scope()` before their own `try:`. `Enumerator._drive` additionally wraps its main body in `except Exception as exc: publish EnumerationFailed; raise` — genuinely correct, better than the other three — but that `except` sits *inside* the same `try`, so it doesn't cover this gap either; the pre-`try` setup is identically exposed in all four.
- **The RF-reservation consequence is real and worse than a cosmetic bug.** `RadioController.release()` (`rf.py`) is a plain, non-raising `self._current = None` — release itself can never be the thing that fails. The only way it's skipped is if its driver thread never reaches its own `finally` at all. `Engine.shutdown()`'s job-wait loop is already timeout-bounded (`SHUTDOWN_JOB_WAIT_TIMEOUT_S` per job) and `release_to_managed()` runs unconditionally, so a leaked reservation does *not* hang shutdown or leave the adapter stuck in monitor mode after AirCommand closes — the damage is scoped entirely to the remainder of the *live* session: every subsequent `reserve()` call raises `AdapterBusy` until restart.
- **`mark_terminal`'s DB write can't just be retried against the main connection.** `persistence/db.py`'s connections are `check_same_thread=True` by design (see `jobs.py`'s own test-fix note on this), so a background thread calling `mark_terminal(job_id)` with no `repo=` falls back to the *main* connection and raises `sqlite3.ProgrammingError` immediately — confirmed by re-reading `JobRegistry.mark_terminal`, not assumed. This is exactly why the DB write and the in-memory cleanup (`_tokens`/`_terminal_events`) need to be decoupled: the in-memory half is the only half that can still succeed when `_new_connection_scope()` itself is what failed.
- **Crack's bug is confirmed against the real code**, not a secondhand claim: `crack.py` lines 85-105. `handle.lines()` yields nothing if `hashcat` exits immediately; the `finally` only ever checks `outfile_path.exists()` and `token.is_cancelled()` — a crash and a legitimate empty result are indistinguishable, and the crash reads as the legitimate one. `domain.py`'s `CrackOutcome` is explicitly documented as a sealed `Found | Exhausted | Aborted` set — adding a fourth variant isn't the right fix; `CrackResultRow.stop_reason: StopReason` already exists to carry exactly this kind of "don't trust this as a definitive result" signal, the same way `Capture._drive` already uses `StopReason.ERROR` without needing a new outcome type of its own.
- **`CrackPanel._format_result` (`crack_view.py`) ignores `stop_reason` entirely today** — it branches only on `isinstance(result.outcome, ...)`. Fixing `crack.py` alone without touching this would make the audit *data* correct while the GUI still displays a crashed run as a plain "Exhausted (not found)," silently defeating the point — confirmed by reading `_format_result` directly, not assumed.

## Considered Options

- **A shared `job_safety_net` wrapper in `jobs.py`** (e.g. a decorator or helper each `_drive()` calls into, taking the driver's body plus an optional cleanup callback) — this was the shape an earlier investigation proposed. Rejected: the four drivers' `_drive` signatures and required cleanup differ (RF release for three of them, none for Crack; `EnumerationFailed`'s extra `except` for Enumerator only), so a generic wrapper would need a nontrivial callback-passing interface to stay correct for all four — more new cross-cutting machinery than the actual failure surface (one call, `_new_connection_scope()`, per file) justifies. Inconsistent with this project's own established preference for a small, local fix over a new shared abstraction when the local fix fully closes the gap (see ADR-0008's own Consequences on deliberately *not* applying its stdout-decoupling pattern to Crack/Enumerator "to match a pattern that doesn't apply to them", and `docs/roadmap.md`'s repeated "not ADR-worthy... applies an already-established pattern" notes).
- **Give Crack a new `CrackOutcome` variant (e.g. `Errored`) instead of reusing `StopReason.ERROR`.** Rejected — `CrackOutcome` is explicitly documented as a sealed three-member set; `StopReason` already exists specifically to carry this distinction (Capture's own `StopReason.ERROR` usage is the precedent), so adding a fourth outcome variant would duplicate information the row already has a field for.
- **(Chosen) Harden `mark_terminal` once, widen each driver's own `try:` by one line, and give Crack the same exit-code-based `StopReason.ERROR` inference Capture already has — no new abstraction, each fix lives exactly where the gap it closes lives.**

## Consequences

- `JobRegistry.mark_terminal()` (`jobs.py`) always completes its in-memory cleanup (pop `_tokens`, set the terminal `threading.Event`) even if the DB write fails for any reason — not just the cross-thread-connection case this ADR was found from. This is a strict widening of an existing guarantee, not a behavior change for the success path.
- All four `_drive()` methods gain a `db_scope = None` (and, for `Crack._drive`, `handle = None`) initialized before the now-widened `try:`, with every `finally`-block use of `db_scope`/`handle` guarded by a `is not None` check. If `_new_connection_scope()` itself fails, **no row can be written for that job in any facade** — by definition, since the write needs the very connection that failed to open. What this ADR *does* still guarantee even then: the in-memory job registry and (for Discovery/Capture/Enumerator) the RF reservation are released correctly, so the live session keeps working; the stale `RUNNING` row is cleaned up by the existing ADR-0004 reconciliation pass on next launch, exactly as it already handles every other crash shape — unchanged.
- `Crack._drive` calls `handle.wait()` once its `for line in handle.lines()` loop ends (cancelled or exhausted) to get `hashcat`'s real exit code, and uses it — only when there's no plaintext and no cancellation — to decide between `stop_reason=StopReason.COMPLETED` (`returncode == 0`) and `stop_reason=StopReason.ERROR` (anything else, including `handle` never having been bound at all). `outcome` stays `Exhausted()` either way; `stop_reason` is the only new signal.
- `CrackPanel._format_result` (`crack_view.py`) must check `result.stop_reason` before falling back to the outcome-based text — on `StopReason.ERROR`, show that the run failed rather than "Exhausted (not found)", the same distinction `CapturePanel._on_stopped` already surfaces via `event.reason.value`.
- `rf.py` needs no changes — `airmon-ng start`/`stop`'s deliberate exit-code-ignoring (its own existing comment) is untouched; this ADR only ever reads `AdapterReservation`/`release()`, never writes to `rf.py`.

## Implementation plan

Mechanical, file-by-file — safe to implement directly from this list.

1. **`aircommand/core/jobs.py` — `JobRegistry.mark_terminal`**
   Wrap the existing `(repo or self._repo).mark_terminal(job_id)` line in `try: ... except Exception: logger.exception("mark_terminal DB write failed for job %s", job_id)`, keeping the rest of the method (the `with self._lock:` pop/set block) unconditional and unchanged. Needs `import logging` + a module-level `logger = logging.getLogger(__name__)` if not already present (check first — `rf.py` and `events.py` already have this pattern; `jobs.py` currently does not).

2. **`aircommand/core/discovery.py` — `Discovery._drive`**
   Move `db_scope = self._new_connection_scope()` from before `try:` to the first line inside it; add `db_scope = None` on the line immediately before the (now-widened) `try:`. In `finally`, change `self._jobs.mark_terminal(job_id, repo=db_scope.jobs)` to `self._jobs.mark_terminal(job_id, repo=db_scope.jobs if db_scope is not None else None)`, and wrap `db_scope.close()` in `if db_scope is not None:`.

3. **`aircommand/core/capture.py` — `Capture._drive`**
   Same shape as item 2: `db_scope = None` before the widened `try:`, move `db_scope = self._new_connection_scope()` to the first line inside it (after it — `handshake_seen`/`burst_count`/`handshake_pacer`/`deauth_pacer` stay before `try:`, they're trivial and don't need the guard), same `finally` guards.

4. **`aircommand/core/enumerate.py` — `Enumerator._drive`**
   Same shape: `db_scope = None` before the widened `try:`, move `db_scope = self._new_connection_scope()` inside it as the first line. The existing `except Exception as exc:` clause is untouched (it already sits inside `try`, after the move). Same `finally` guards on `db_scope.jobs`/`db_scope.close()`.

5. **`aircommand/core/crack.py` — `Crack._drive`**
   - Add `db_scope = None` and `handle = None` before the widened `try:`; move `db_scope = self._new_connection_scope()` to the first line inside it.
   - After the `for line in handle.lines(): ...` loop, nothing new needed inline — the exit-code read happens in `finally`.
   - In `finally`, add `returncode = handle.wait() if handle is not None else None` as the first line (before the existing `plaintext = ""` block).
   - Change the `stop_reason` computation from `StopReason.CANCELLED if token.is_cancelled() else StopReason.COMPLETED` to: `StopReason.CANCELLED if token.is_cancelled() else StopReason.COMPLETED if (plaintext or returncode == 0) else StopReason.ERROR`. `outcome`'s existing computation (`Found`/`Aborted`/`Exhausted`) is unchanged.
   - Wrap the `row = db_scope.crack_results.insert(...)` and `self._bus.publish(CrackResult(...))` calls in `if db_scope is not None:` (nothing to insert against or report if the connection itself never opened).
   - Change `self._jobs.mark_terminal(job_id, repo=db_scope.jobs)` to the same `if db_scope is not None else None` guard as the other three files, and guard `db_scope.close()` the same way.

6. **`aircommand/gui/crack_view.py` — `CrackPanel._format_result`**
   Check `result.stop_reason` before the existing `isinstance(result.outcome, ...)` chain: if `result.stop_reason == StopReason.ERROR` (new import: `from aircommand.core.domain import StopReason`, alongside the existing `Exhausted, Found` import), return something like `f"Failed to complete (exit error) — wordlist {result.wordlist_path.name} — {...}"` instead of falling through to the outcome-based text, mirroring the detail level `CapturePanel._on_stopped`'s `f"Stopped ({event.reason.value})"` already uses.

### New/updated tests

- **`tests/test_jobs.py`**: new test asserting `mark_terminal` still pops the token and sets the terminal event when its repo write raises — construct a `JobRegistry` with a repo whose `mark_terminal` raises (a small test double, or `unittest.mock.Mock(side_effect=Exception)`), call `new_job()` then `mark_terminal()`, assert `wait_for_terminal(job_id, timeout=...)` returns promptly and `job_id not in registry.active_job_ids()`.
- **`tests/test_discovery_acceptance.py`** (and the equivalent spot in `tests/test_capture_acceptance.py`, `tests/test_enumerate_acceptance.py`): new test where `new_connection_scope` (the `Callable[..., ConnectionScope]` constructor param every `Engine`-built facade already takes — check `engine.py` for the exact injection point, likely needs a thin test-only override rather than a new constructor param on the facade itself) raises on its first call. Assert: `handle.wait_for_test(timeout=...)` returns (doesn't hang), and a second `engine.discovery.start()` (or the Capture/Enumerate equivalent) right after succeeds rather than raising `AdapterBusy` — this second assertion is the one that actually proves the RF-reservation leak is fixed, not just that the thread didn't hang.
- **`tests/test_crack_acceptance.py`**: new test using `FakeProcRunner(..., returncodes={"hashcat": 1})` (already-supported per-argv override, confirmed in `procutil.py` — no new test infrastructure needed) with a `hashcat_key=None` on_spawn (no outfile written, matching a real crash leaving nothing behind) and a short/empty scripted line list for `"hashcat"`. Assert the resulting `CrackResult.result.stop_reason == StopReason.ERROR` and `outcome == Exhausted()` (confirming `outcome` is deliberately unchanged, only `stop_reason` differs from today's — wrongly — `COMPLETED`). Note: `_make_engine`'s `FakeProcRunner(...)` construction in that file doesn't currently pass through a `returncodes=` kwarg — needs a one-line addition to `_make_engine`'s own signature/body, or the new test should construct its own `Engine`/`FakeProcRunner` directly instead of reusing `_make_engine`, matching whichever this file's own existing convention favors for a one-off scenario (check the other tests in the file before deciding).
- **`tests/test_crack_view.py`**: new test driving `CrackPanel._format_result` (or a full `_on_result` round-trip, matching that file's existing idiom) against a `CrackResultRow` with `outcome=Exhausted()`, `stop_reason=StopReason.ERROR`, asserting the displayed text differs from the plain `stop_reason=StopReason.COMPLETED` case's "Exhausted (not found)".

Run the full suite (`pytest -q`) after each file's change, not just at the end — every file in this list already has passing coverage today; a regression should be caught at the file that introduced it, not discovered three files later.
